# Draft issues for bendlang/bend, found moving bend-frame from 2.0.36 to 2.0.39 (not filed)

All three are reproducible from this repository on macOS arm64 (Apple M2 Pro), Bend 2.0.39 from `bend update`.

## 1. `--verdict` / `-o X.bendtt` overflow the machine stack on a large proof file (regression)

`bend PROOF.bend` prints ALL PROOFS CHECK in both versions. `bend PROOF.bend --verdict` printed ALL PROOFS CHECK on 2.0.36 (~40 s) and prints
`Error: the machine stack overflowed (a deep recursion, or a literal too large to expand)` on 2.0.39, with no location. `bend PROOF.bend -o out.bendtt`
overflows the same way, so it is the translation to BendTT, not the Lean kernel. (Inside `make mutation-check` the same message appears with a `Location:` for
deliberately broken proofs, which is the expected rejection.) PROOF.bend imports 22 files (~150 laws, the largest term is the stack-machine typing proof in
`PROOF_evalrun.bend`); I did not reduce it further.

Repro: `git clone` this repo, `bend PROOF.bend --verdict`.

## 2. `bend FILE.bend` (run mode) uses ~10x the memory and is 3-7x slower than 2.0.36; `-o` binaries are not affected

`bend tests/csvprod.bend`: 2.0.36 2.6 s, 0.5 GB max RSS; 2.0.39 14 s, 5.2-5.7 GB (the `bend` process itself, no child). `tests/csvlane_lines.bend`: 7.8 s / 0.45 GB ->
58 s / 6.5 GB. `tests/csvlane.bend`: 8 min. The same programs built with `bend X.bend -o x` and run natively take the same time on both versions
(`csvprod` ~5 s). `--check-only` is the same speed (0.1-0.2 s).

## 3. Runtime flags moved to `+RTS ... -RTS` without a note (behaviour change)

2.0.36 binaries took `./prog --threads 4 args...` and removed the flag from `IO.args`. 2.0.39 binaries pass `--threads 4` through to `IO.args` and expect
`./prog +RTS --threads 4 -RTS args...`. A program that used the old spelling silently gets two extra arguments (here: it tried to open a file named "1").
A one-line warning for a bare `--threads` would have found it at once.
